# 大运河历史地图第二版需求设计

日期：2026-11-02。状态：供用户确认的具体方案；尚未开始网页实现。

已确认：关键年份／事件切片为时间单位，朝代保留为导航。继续使用本地文件夹、纸色历史地图、来源可追溯与历代运河叠加。研究依据见[补充研究](补充研究.md)。下文缩放阈值和性能数值都是开发目标，不是历史事实。

## 目标

用户在一个历史时间切片下，能找到一条河，逐级看清支流和汇流关系，看到运河接入何处、由谁建设和控制、服务或影响谁，以及这些结论依据什么。地图既服务历史阅读，也为未来经营游戏提供可以复用的数据结构。

## 方案取舍

| 方案 | 优点 | 代价／不足 |
|---|---|---|
| A：给现图补河名和若干支流 | 改动少 | 放大仍无真实细节，政治关系仍挤在文字里 |
| B：分级河网＋关键时间片＋政治关系，推荐 | 全国概览与流域细节统一；数据可追溯；离线可用 | 需要河名匹配、分包、时态数据与渲染改造 |
| C：全国逐年精确河道与疆界复原 | 理论上最全面 | 缺少覆盖所有年代的可靠几何、许可和历史水文资料，无法负责任地承诺 |

建议采用 B；先以汉江、鸿沟和破岗渎做完整样例，再用相同标准扩展现有全部工程与其他主要流域。不会把只做完样例称为整个第二版完成。

## 1. 地图与分级细节

主画面为地图，左侧流域／工程目录，右侧随选择显示河流或工程档案；底部时间轴。保留纸色、墨线、朱色人工运河，政治区域淡色填充，避免压住水系。

用地图中心地面分辨率控制细节，屏幕显示实际公里比例尺，不能用浏览器窗口大小假装固定纸图比例尺。初定阈值：

| 地面分辨率 | 默认显示 |
|---|---|
| 大于 2 km／CSS像素 | 主要流域干流、重要运河、当前政治实体名；汉江必须可见可认 |
| 0.5—2 km／CSS像素 | 主要命名支流、流域边界、重要湖泊和城市 |
| 0.1—0.5 km／CSS像素 | 更多支流、汇流节点、可靠的设施和古今地名 |
| 小于 0.1 km／CSS像素 | 显示可用数据上限与精度说明；不增加虚构折点或无来源小溪 |

阈值含边界规则：2 归第二档、0.5 归第三档、0.1 归第三档。河流选择后可临时强制显示该河及连接干流，避免缩放隐藏搜索结果。显示等级由河级、集水面积和命名重要性共同决定；须保持干流连续，不能只剩支流。线宽是符号权重，不代表历史实际河宽。

全国基底采用同一河网的多级简化版本，避免低倍率 Natural Earth 与高倍率 HydroRIVERS 生硬切换造成河流跳位；Natural Earth 保留陆地轮廓及数据核对作用。简化时保持汇流节点和连通关系。性能较高的细河网用 Canvas／WebGL 之一，文字和交互使用可访问的界面层；最终技术选择以本地样例性能为依据。

## 2. 汉江必做专题与全国覆盖

首批核名范围：汉江／汉水、褒河、湑水河、牧马河、子午河、任河、月河、旬河、岚河、堵河、丹江、唐白河、唐河、白河、南河、蛮河、汉北河。丹江次级支流继续按补充研究名录匹配，摘要条目补核后才标为已核名。

支持搜索河流、运河、古今地名、政治实体；搜索“汉水”和“汉江”得到同一主体，“白河”等同名对象必须展示流域和地区供选择。点击一条河，可突出直接支流、整条下游路径及所属流域，显示连接的运河。上下游拓扑并不等于通航路线，不直接生成商船航线或旅行时间。

全国现代河网按资料覆盖供逐级浏览，主要命名审核优先覆盖汉江、黄淮、海河、江南、湘漓与浙东。显示每个流域的覆盖和核名状态，不把一片空白当作该地古代没有水系。

## 3. “自然水系”与“历史河道”分开

三类几何：现代地理参照；有年代及依据的历史复原；文献走廊／位置示意。每条线记录资料时期、有效期、来源和空间精度，颜色之外再用线型区分。

默认可用现代参照帮助定位，但图例常驻“现代参照，不代表所选年代河槽”；提供只看历史证据模式。现代水库只出现在现代参照层，不能伪装为古代天然湖泊；缺少建库前线形时显示缺口或走廊。

汉江入江口争议、黄河夺淮、鸿沟渠首变化作为变迁专题。争议可切换研究观点；只有资料支持时才显示前后线形，不为动画效果补造过渡河道。

## 4. 时间片与政治实体

时间轴选择关键年份或有起止范围的事件；同一年变化有先后时使用“事件前／后”标签。不在两个切片间自动插值疆界。早期拟选事件为邗沟开凿、鸿沟阶段变化、秦灵渠、楚汉分界、东汉末白沟、孙吴破岗渎；随后补南北朝并存、隋工程、唐漕运、北宋与辽、南宋与金、元漕运、明复修、清治河、近现代。具体切片日期与控制区逐项有依据后启用。

“吴（春秋）”和“孙吴”，“魏（战国）”和“曹魏”各有独立 ID。皇朝、地方政治集团、行政区和管理机构是不同类型；人物单独关联。首都和治所按有效期记录，替换旧版单一朝代首都高亮。

地图显示当前切片的并存政权、都城／治所和已核控制区域；有可靠依据才显示详细边界，近似范围用虚线或晕染并标“控制区示意”，未知处明确标注。名义归属、实际控制和争议区不得混成一种填色。

## 5. 每条运河的政治与社会档案

现有每个工程均补齐下列栏目；缺证据填“未核”，不以大段推测顶替：

- 谁下令、谁组织建设，谁承担财政和劳役。
- 选中时间片下，各河段经过哪些控制区；来源不足则列已知节点。
- 谁管理、维修和征收，哪些都城、仓储、粮源区依赖此线路。
- 关联政权的角色：实际经过、供应受益、资源承担、军事目标、竞争／冲突、环境损失。
- 关系发生的时间、原始记载或研究解释、可信程度及反例／争议。

地图的实线代表实体水道，箭头代表有证据的供给或军事关系；“远程影响”不能涂成被该政权统治的区域。点击某个政权反向列出与其有关的工程和角色。工程成本继续保留人数、工、粮、货币、免税及原单位；不合计不同朝代币值，不用现代流量估算古代运力。

## 6. 历代叠加与比较

保留全部人工运河叠加总图，可按工程首次开凿／本次修治时代着色并说明口径。全国叠加模式默认关闭政治填色，避免不同时代领土同时显示成同一现实；可锁定一个政治时间片作参照，常驻提示“运河跨时代，政治图仅为所选切片”。

新增两个时间片对比，可切换突出新增、废弃、改道、控制主体变化。只有两端均有证据时才显示变化结论。自然河道不能跨代全部叠加后不加说明。

## 7. 数据结构与证据

| 对象 | 必要信息 |
|---|---|
| 河流主体 | 稳定 ID、分时别名、流域、所含河段、名称证据 |
| 河段与节点 | 上下游节点、方向、几何版本、来源年代、显示等级、有效期、空间精度 |
| 工程 | 分段、工程事件、费用、状态、与天然河网的连接 |
| 政治实体 | 稳定 ID、类型、名称有效期、存在区间、从属关系 |
| 控制记录 | 实体、河段／地点／区域、时段、实际／名义／争议、空间证据 |
| 影响记录 | 工程、关联实体、角色、作用机制、时段、指标、证据级别 |
| 论断与来源 | 原文位置、核读范围、支持／反对关系、许可、变更记录 |

历史纪年 UI 不出现公元 0 年；内部存储约定统一并测试跨公元前后的比较。未知有效期不等于永远有效。一个工程可以有多次修治与废弃状态，不再由 activeEras 代替真实时间。

## 8. 离线交付、性能及失败处理

交付本地独立第二版目录和启动入口，详细地理数据按流域和显示层级分包、随视窗按需载入；完成打包后运行不依赖外网。优先使用本机静态服务以支持分包，启动入口只运行本项目的本地服务并检查端口；网页内提供清楚的打开说明。

第一版单文件继续保留用于对照；第二版可额外导出轻量单文件摘要，但不强求把所有详细河网塞进一个 HTML。地图导出包含图例、时间片、地理数据版本和精度提示。资料导出 JSON／GeoJSON／CSV。

性能目标：在记录配置的本机浏览器测试，缓存后的全国首屏不超过 3 秒；常用流域切换不超过 1 秒；连续缩放拖动目标至少 30 FPS。记录实测结果，不凭估计宣称达标。数据包失败时显示“该层未载入”及重试，不悄悄换成低精度线；无法定位的来源记录仍能从目录打开。

键盘可搜索、切片、选择河流、开关图层；颜色以外有线型、文字和列表；窄屏地图与详情切换避免互相挤压。

## 9. 完成顺序与范围

先取得可用河网并完成汉江核名与连通检查；同时完成鸿沟、破岗渎的时间与政治关系样例。通过详细度和史料正确性检查后，扩展全国参照水系、现有工程政治栏目与各历史阶段的已核切片，完成对比、离线包与总图。

第二版不宣称复原全国每年每条古河道，也不承诺全国历代县界。区域证据不足时交付明确的未核清单，但核心样例和水系分级功能必须完整，不能用“待补资料”替代用户指出的问题。具体通过条件见[验收清单](验收清单.md)。
