# 大运河游戏需求文档

版本：v0.1　日期：2026-11-02　关联：[架构](02-architecture.md) · [美术](03-art-direction.md) · [执行计划](superpowers/plans/2026-11-02-grand-canal-mvp.md)

## 1. 产品定义

以历史中国水运为背景的单人策略经营游戏。玩家作为跨越具体统治者的“天意”，通过修建、改造、维护和经营运河，回应人间各方的祈愿，观察运河怎样影响民生、地方利益与国家命运。

核心体验：有限资源下的路线和工程取舍；同一条河在不同局势下用途变化；多年后能辨认自己的决策留下了什么。

### 1.1 已确认的产品决定

|编号|决定|
|---|---|
|D01|运河经营是细节玩法，国家治理与历史抉择是整体脉络。|
|D02|玩家代表“天”或长期意志，直接决定运河方案；各方不能因一次随机判定完全忽略有效指令。|
|D03|货物与运输需求随局势自动产生，玩家不经营逐件商品、船只采购或逐船订单。|
|D04|战争、宫殿、地方工程等由人间各方自主决定，并与运河争用财力、粮食和劳役。|
|D05|人口、当期劳力、累计徭役负担分别计算，建设、维修与其他征发共同造成社会代价。|
|D06|用关键节点推进时间；日历跨度与玩家等待时间分离。|
|D07|中央、皇室、地方、百姓、商旅通过祭祀交流需求和反馈。|
|D08|保留是否修、何处何时修、规格、维护/改道/退出、通航管理五组决策。|
|D09|历史真实性主要体现于地理、制度条件和因果；数值与操作可做明确标注的抽象。|
|D10|天下结局与玩家河道遗产分别评价，显示外部事件和玩家行为如何共同影响结果。|

### 1.2 开发基线

- 平台：桌面浏览器，简体中文，键鼠操作，本地存档；默认无需模型服务即可完成一局。
- 第一剧本：以明初江淮—会通河—南旺—北方供给走廊为背景。时间窗口设为 1410 年初至 1425 年初，属于十五年的游戏观察期，不代表这段时间所有事件按历史强制复现。
- 地图：十个抽象区域、约二十条可经营/候选河段，另有天然水道及少量陆海替代边。区域与节点清单由剧本数据定义，数量是复杂度预算。
- 时间：内部每月上、中、下旬三步，每年 36 步，是简化历法；界面不伪装为准确古历换算。主要向玩家展示关键节点。
- 首局目标：20—30 次关键决策、30—60 分钟。此为试玩假设，不是保证；优先减少空操作。
- 数据范围：先使用代表性走廊，后续剧本扩充历代路线库。跨朝连续继承纳入新增长剧本，按 C01—C05 分期交付。

## 2. 玩家权限与世界自主性

### FR-01 运河权限

玩家可选择修建、疏浚、扩建、改道、分期、暂缓、恢复、封存或退出；选择工程规格、开始时机与河工征发强度；设定维护、用水和通航原则。每项动作都必须指向河段、设施或明确的河工项目。

计划在提交前可自由比较；提交后的施工、占地、征发和支出按进度产生。停止工程不能取回已消耗的资源。费用、工期和结果必须可解释。

### FR-02 自主的人间事务

中央、皇室、地方各有独立的政策倾向、资源和承诺。战争、宫殿、非运河水利、地方建设会改变资源供应、征役和运输需求。玩家通过运河方案适应或间接影响它们；首版不提供宣战、取消宫殿、改税制等独立政务操作。

外部事务通常经历“意向/预警—开始—持续征用—结束/升级”。已付出的河工工作量不能被事件直接抹除；后续资源承诺可以因事件撤回，并记录来由。条件被玩家改变时，相关事件可以改变或不发生。

## 3. 时间与循环

### FR-03 关键节点推进

循环：查看地图和祈愿 → 比较方案 → 提交河道安排 → 推进到下个关键节点 → 查看已发生后果 → 调整。

停点包括：工程阶段完成、资源承诺显著变更、灾害临界风险、运输瓶颈升级、需要玩家取舍的祭祀冲突、剧本结束。普通信息进入纪事，不逐条强制暂停。

跳时必须逐步结算；不能漏过中间的断粮、死亡、失修、工程完工或可响应的灾害。玩家可随时暂停、单步观察或选择推进至一个较早日期。相同原因的警报合并，已知且未变化的风险不重复打断。

### FR-04 决策预测

提交前显示确定的投入与当前条件下的预计效果：可投入劳力、预计完工区间、维护负担、主要受益与受损地区、已知资源竞争。历史资料的不确定性、未来事件的不确定性分别说明。

预览沿用正式规则计算，不能改动正式存档、消耗正式随机序列或承诺未来一定丰收。选择受资源约束时明确显示缺口与可缩减方案。

## 4. 人口与资源

### FR-05 人口、劳动与役负

人口是长期状态；劳力是地区在某期能够提供的劳动量；役负是连续征发造成的累计负担。

- 征发河工不会按人数直接扣人口；出生、死亡、迁入迁出通过各自事件改变地区人口。
- 农业与生活必要劳动、军役、宫殿、地方工程、运输和河工共享同一劳动预算。
- 正常工程优先使用农业保护线之外的余力；加急征发可挤占农业，但必须显示减产与役负风险。任何分配不得超过实际劳动上限。
- 役负按劳力来源地区记录，包括非玩家工程。负担在减役后逐步恢复；不是一笔花完即清零的货币。
- 财力与工程粮食具有归属和位置；可调用资源来自已承诺投入，不能直接取用全国总量。
- 维修同样占用资金、物资和劳动；运输时间和供给中断可使有预算的项目仍然停工。

### FR-06 工程生命周期

生命周期：勘察 → 计划 → 施工 → 试航 → 运营 → 降级/封存/改道/退出。维修和升级可作为运营期间的子项目。

路线比较至少包含成本区间、工期区间、水源条件、可航能力、维护需求与地区负担。地形、水源、技术前提不满足时，说明具体原因；地图上有线不等于当时可建。

封存需要最低保全支出；退出涉及必要的泄水、岸坡或既有设施处置。遗弃不能成为免费消除全部责任的按钮。改道保留旧道的地区影响与退出成本。

## 5. 水与运输

### FR-07 水利约束

表示河段水位/水源保障、季节来水、闸坝、蓄水设施、淤积和维护状态。水量不足限制可航条件；船闸通行有时间和补水约束；蓄水改变供水时机，不能凭空造水。防洪、农业用水和通航可能冲突。

水的连接与船的连接分别定义。天然河流不默认全年可航；交叉线不自动成为可换水、可换船的节点。首版使用简化网络水量模型，不要求流体仿真。

### FR-08 自动货流

地区产出、消费、国家行动和灾害自动形成运输需求。需求至少有来源、目的地、用途、数量、期限和来源事件。用途可为民生、官运、商运，但不是要求玩家手动经营三类商品。

系统自动选择符合政策和能力的线路，并考虑共享运力、旅行时间、装卸瓶颈、损耗与替代路线。收益在相应运输和消费发生后体现，不因挖通一段线立即获得固定永久加成。

玩家看到河段利用率、可靠性、拥堵原因、供给改善和流量构成；可设定官民通航次序、错峰、限载、养护封航及用水优先原则。首版不增加细粒度价格市场或逐港税率操作。

### FR-09 地区变化与替代

民生、商业、税源和地方关系随实际供给、负担与风险变化。新线可能使旧港镇失去流量。必要时用既有陆路、海路或短驳作为后台替代，使“不新建”“维护旧道”和“主动退出”成为可行策略。边远地区的矛盾不强制用运河解决。

## 6. 祭祀与反馈

### FR-10 多方祈愿

每件祈愿包含主体、位置、诉求、原因、相关河段、时限/紧迫性、受影响人群及事实引用。同一问题的多方意见聚合呈现。

中央、皇室、地方官、百姓、商旅的语言和关注点不同。祈愿允许偏见和有限信息；工程条件、资源账本与已发生后果提供可核对的事实层。祭祀是游戏叙事设定，具体仪式、服饰和称谓按剧本时期考据。

玩家回应是地图上的河道安排。有效指示成为正式计划，资源制约表现为工期、规模、可运行能力变化；不追加随机“神谕被无视”判定。首版不引入独立信仰货币或超自然造水能力。

### FR-11 原因与学习

重要变化附简短原因链和来源类型：玩家指令、人间事务、自然变化、系统结算。可展开区域与工程明细。每个教学知识点关联一次真实的决策反馈，例如瓶颈、枯水补给、误农、替代线路、维护债务。

史实卡分为“史料记载”“研究解释”“游戏抽象”；史料数值缺失时显示未知。游戏系数不得回写成历史事实。历史线路、技术前提、地理状态均有有效时期与依据。

## 7. 结束、复盘与存档

### FR-12 双重结局

正常结束为观察期结束；提前结束为剧本定义的持续政权/供给危机在预警和补救窗口后达到终止条件。普通缺钱或一次灾害不立即结束。

首版提前终止实验阈值：核心地区连续六个旬末处于生存供给临界且国家执行能力连续三个旬末低于终止阈值。首次达到预警线时停下，让玩家至少拥有一次有意义的响应机会；阈值保存在剧本参数并通过试玩校准。

同时生成：

1. 天下结局：民生、财政、地方关系、国家供给和外部冲突。
2. 河道遗产：可靠性、受益范围、累计徭役/损害、未来养护负担与后世可沿用性。

称号根据多维条件组合，不只依赖总分。不修新河不自动判无为；主权相关称号需要对应事件。评价使用全局累计影响、末期多期表现和既有设施的后续维护需求，避免末回合透支获利。复盘列出已确认的影响链；未经专门反事实计算，不声称精确算出“若没有玩家会怎样”。

### FR-13 存档与复现

自动存档发生在抵达关键节点、该旬事件已结算之后，玩家提交下一个指令之前；读入该档不会撤销已经发生的灾害。另保留最近一个稳定快照用于故障恢复，允许命名手动存档和导入导出。保存剧本/规则版本、随机状态、资源承诺、在建工程、在途运输与事件位置。同版本同种子同指令应产生同一模拟结果；文案变化不得改变结果。损坏或版本不兼容的文件给出说明并保留原文件。

## 8. 范围与非功能需求

|编号|要求与首版目标|
|---|---|

|NFR-02|界面主要操作即时响应；模拟在 Worker 中运行并可分批让出执行。|
|NFR-03|以约定测试机测量：选段/打开面板 P95 <100ms，常规下一节点推进 P95 <1s；属于验收目标，记录硬件、浏览器和场景后报告实测。|
|NFR-04|支持 1280×720 至 2560×1440；正文基准 16px，可放大；颜色同时配线型/图标/文字，支持减少动效和键盘焦点。|
|NFR-05|默认不上传存档。可选在线文案仅提交必要事件摘要，密钥保存在服务端。|

## v0.2 新增长剧本

用户已要求加入隋前至唐末五代十国的剧本，见[长剧本规格](05-sui-tang-campaign.md)。FR-14—FR-19 是本需求的组成部分。明初十五年继续作为基础验证场景；550—980 长战役支持独立章节和真实状态继承。长战役的政权覆亡按继替处理，不沿用明初单政权结束条件。
