## 文件与契约

- `package.json`、`package-lock.json`、`.npmrc`、`.node-version`、`.gitignore`、`tsconfig.json`：精确工具链、严格类型检查与目录内生成物忽略。
- `src/core/types.ts`：地区、主体/行动、库存、双网络、河段、工程、保全责任、承诺、需求、在途批次、祈愿、事件、账本及状态/剧本完整字段；快照深只读，数值为安全整数或万分固定点。没有任意状态 payload、函数或 Map。
- `validation.ts`、`createGame.ts`、`immutable.ts`：严格 JSON/字段校验、唯一 ID 和实体引用检查、范围/容量/日程校验；深复制调用者剧本、按稳定 ID 排序、冻结独立初态。初态具备版本、revision、RNG、命令去重集合、队列、在途集合及 ending。
- `rng.ts`：全安全整数种子参与初始化；天气、人物事务、灾害为三个独立 uint32 流，纯函数返回新状态和随机值。显示/文案不持有或消耗正式随机流。
- `hash.ts`：对象键按 UTF-16 字典序规范化，数组顺序保留；拒绝有损 JSON 值与环。FNV-1a 64 按 UTF-8 计算整个状态哈希，无 Node 专用导入、真实时间或随机依赖；不承诺抗碰撞安全。
- `calendar.ts`：一年 12 月、每月三旬；`tick` 为已完成旬数。起始年和结束旬由剧本决定，没有全局明初起始年/540 结束常量。
- `reducer.ts`、`tick.ts`：确认 `TICK_COMPLETED` 后一次提交时间、revision、当旬静止账本和结束标记。失败抛出带 tick/eventId/reason 的 `SimulationError`，原状态保留；拒绝错误版本、事件、RNG、失衡账本和未实现的调度队列。不可变输入可共享不可变子树；可变 JSON 快照先分离，再冻结输出。结束后返回原对象和空事件。
- `index.ts`：仅实际实现的 `createGame`、`tick`、`hashState` 及类型；日历、RNG 等模块有各自具名导出。不提供 `applyCommand`、`preview` 或 `advanceToDecision` 占位。
- `tests/fixtures/scenarios.ts`、`inspect.ts`、`tests/core/determinism.test.ts`：仅 minimal 夹具、真实状态/账本指标和旬推进辅助；其他夹具尚未建立。
- README 和计划：更新实际命令/状态；纠正旧 `murder-loop-ai` 源目录。

公共签名沿用 T01 契约：`createGame(scenario, seed): GameState`、`tick(state, scenario): StepResult`、`hashState(state): string`。`StepResult.events` 为只读确认事件。序列化状态为新建的 `foundation-1` 契约，没有旧版存档迁移；存读/版本拒绝流程属于 T06。
