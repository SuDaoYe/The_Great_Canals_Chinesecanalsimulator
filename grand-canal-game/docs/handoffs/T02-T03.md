## 复核修正

1. **同层分配与征役边界**：保留并实际通过控制器两类独立回归——80/20 请求在 20 劳动池得 16/4，权重 1/2 时得 13/7；征役 `startTick=3/endTick=9` 在 2→3 结算占用 40，状态 3..8 有效、9 完成且 0 劳动。未改测试期望。
2. **安全退出生命周期**：已施工取消或 `SET_REACH_STATUS(decommissioning)` 建立 `PreservationLiability`；只要河段仍为 `decommissioning`，退出劳动进入同一分层劳动账本（层级 3），按实际劳动、工地粮和财政支付，进度累计。资金优先使用取消时保留的托管，再使用责任主体财政；粮来自工地库存。资金或粮不足时退出工作不推进，不得免费解除。达到 `exitWorkRequired` 后责任 `resolved`、河段 `retired`；未使用保留额退回原承诺。维护和暂停/恢复施工仍有既有有效路径。
3. **疏浚实效**：取消“任何疏浚都清零淤积”。按工程等级移除当前淤积的 40%/70%/90%（小型/标准/重型），初始 `minimal` 淤积改为 6000；维护劳动请求随残余淤积增加。大修因此以更高前期费用换取更低残余淤积和后续维护负担，小疏浚保留残余；不再把工作量或不同哈希当作收益。`autumn-segmented` 只是暂停/延迟的小疏浚对照，**当前没有农业季节差异，不能作为秋季策略成立的证据**。
4. **行动撤回可撤回承诺**：`ActorAction.commitmentIds` 显式链接承诺；行动有效旬（`startTick`）的首次旬结算第一阶段撤回未使用的 revocable 额度并停止未来拨付。已消费额度不退；`hard` 托管不被没收；`sourceEventId` 与原出资人守恒保留。工程延期/粮不足仍表现为项目未推进，与承诺 `withdrawn` 状态可区分。

## 关键规则与判断

- 指令优先级、原子失败、事件归约和不可变快照沿用前一版：`STALE_REVISION` → `DUPLICATE_COMMAND` → 目标/时间/阶段/资源；失败保留原状态、RNG 与 revision。
- 工程资金由出资者托管；实际工作按完成单位消耗托管财政和工地粮/物料。取消未开工工程只退未花额度；已施工取消保留完成工作并建立保全责任。
- 安全退出与维护均使用同一劳动账本；退出劳动计入地区役负。退出只对 `decommissioning` 河段运行；未决责任仍阻止重开。
- 疏浚效果取决于工程等级，而不是只增加工作量；残余淤积进入维护劳动请求。初始严重淤积是本轮新夹具假设。
- 行动撤回在有效旬第一阶段、劳动分配前执行；只退 `reserved`，不触碰 `consumed`，`hard` 承诺保持 escrowed。
